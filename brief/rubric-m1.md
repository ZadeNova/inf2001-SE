## Appendix B. Requirements and Rubrics for Milestone 1 (1st half)

For Milestone 1, each team needs to submit a Milestone 1 Report and make a group presentation by Week 6.

### B.1 Requirements for Milestone 1 Report (20%)

#### B.1.1 Content (15%)

The Milestone 1 Report should include a chapter for each of the items as below.

- Introduction
  - Cover page
  - Team members and their contributions
  - Plagiarism declarations
  - Elaborations on AI usage and declarations with changes made on the AI outputs (if available)
- Requirement Engineering (4%)
  - Requirement Elicitation Process
  - Software Requirement Specifications
- Use Cases (5%)
  - Formal use cases
  - Use case diagrams
  - Activity diagrams
- Object-oriented Analysis (4%)
  - Identified key classes with diagrams and relationships among the identified classes
  - Sequence diagrams for the use cases with the identified classes
- Project Management (2%)
  - Work Breakdown Structure
  - Project timeline

#### B.1.2 Presentation (5%)

##### B.1.2.1 Formatting (2%)

- Professionally structured report, clear language, good formatting, references where needed.
- All artifacts align (e.g., requirements ↔ use cases ↔ diagrams).
- Terminology consistent throughout.
- No contradictions.

##### B.1.2.2 Group Presentation (3%)

- The presentation slides should cover the key deliverables for each of the items covered in the Milestone 1 Report.
- The team can choose the number of presenting members and it is not compulsory to have the whole team to make the presentation.
- Logistics information, e.g., presentation date and time, will be shared later.

### B.2 Submissions

- Each team only needs to submit one zipped file including the Milestone 1 Report and the presentation slides.
- The zipped file should be named as: INF2001-M1-Team X.zip. For example, Team P1-1 should name the zipped file as: INF2001-M1-P1-1.zip.
- The deadline for submission is: 11:59PM, 9 Oct 2026 (Friday).

A penalty of **20%** per day for each deliverable will be imposed for late submission unless extension has been granted **prior** to the submission date. Request for extension will be granted on a case-by-case basis. Any work submitted more than 4 days after the submission date will not be accepted and no mark will be awarded.

### B.3 Peer Evaluation

All students need to complete their peer evaluation by 11:59PM, 9 Oct 2026 (Friday). If not, there will be a **10% penalty** for your own peer evaluation mark and the contribution credits will be evenly distributed among the other team members.

### B.4 Rubrics

#### Requirement Engineering (4%)

| Item | Criteria |
|---|---|
| Requirement Elicitation Process | • Comprehensive use of elicitation techniques (interviews, surveys, document analysis).<br>• Clearly documented process, rationale, and stakeholder involvement. |
| Software Requirement Specifications | **Functional Requirements**<br>• Clear, complete, consistent, and well-structured list.<br>• Requirements are specific, testable, and cover all key system features.<br>**Non-Functional Requirements**<br>• Comprehensive and realistic (performance, usability, security, etc.).<br>• Each requirement measurable and justified. |

#### Use Cases (5%)

| Item | Criteria |
|---|---|
| Formal use cases | • All major use cases identified and formalized (name, actors, preconditions, main/alt flows, postconditions).<br>• Flows are detailed and logically consistent. |
| Use case diagrams | • Complete, correct, and neatly drawn UML diagram with all actors, relationships, and use cases.<br>• Consistent with textual use cases. |
| Activity diagrams | • Clear workflows modelled for all key processes (subscription, announcement, notification).<br>• Correct UML notation. |

#### Object-oriented Analysis (4%)

| Item | Criteria |
|---|---|
| Identified key classes with diagrams and relationships among the identified classes | • Comprehensive and accurate.<br>• Shows key entities, attributes, methods, and relationships (inheritance, associations).<br>• Aligns with use cases. |
| Sequence diagrams for the use cases with the identified classes | • All key use cases represented with correct UML interactions.<br>• Diagrams show clear lifelines, messages, and ordering. |

#### Project Management (2%)

| Item | Criteria |
|---|---|
| Work Breakdown Structure | • WBS covers all major project phases (requirements, design, implementation, testing, documentation, project management).<br>• All tasks are logically decomposed into manageable subtasks.<br>• Clear hierarchy with correct levels (phases → tasks → subtasks).<br>• Proper numbering/coding scheme (e.g., 1.1, 1.1.1). |
| Project timeline | • Timeline clearly maps tasks from WBS, with realistic start/end dates, task durations, dependencies, and milestones.<br>• Readable and professional. |

#### Presentation (5%)

| Item | Criteria |
|---|---|
| Formatting | • Professionally structured report following the required template, with clear headings, numbering, captions, figures/tables, references where needed, and consistent formatting throughout.<br>• Clear and grammatically correct language, with consistent terminology across all sections and artefacts.<br>• Strong alignment and traceability across requirements, use cases, final class diagram, component diagram, detailed design, testing artefacts, and prototype wireframes.<br>• No major contradictions, inconsistent naming, missing labels, or presentation issues that affect readability or understanding. |
| Group Presentation | • Presentation focuses on the key deliverables for each item covered in the Milestone 1 Report, including requirements, use cases, object-oriented analysis, and project management.<br>• Key deliverables are presented clearly and coherently, with clear alignment between requirements, use cases, diagrams, and analysis artefacts.<br>• Requirements and stakeholder inputs are clearly explained, showing how the team identified, organised, and prioritised the proposed system needs.<br>• Use cases, use case diagrams, activity diagrams, class diagrams, and sequence diagrams are explained clearly and are consistent with one another.<br>• Project management deliverables, such as the work breakdown structure and project timeline, are presented clearly and realistically.<br>• Presentation is clear, professional, well organised, delivered within the allocated time, and the team can justify their analysis decisions and respond to questions. |
